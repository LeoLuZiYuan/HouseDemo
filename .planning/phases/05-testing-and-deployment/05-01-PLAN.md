<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client (GitHub Pages) → Backend API (Heroku) | Untrusted CORS origin, API requires auth for admin endpoints |
| Admin User → API | Authentication via JWT token in Authorization header |
| Database (Heroku PostgreSQL) → Backend | Internal, managed by Heroku; credentials via DATABASE_URL env var |
| Frontend Build (GitHub Actions) → GitHub Pages | Deployment artifact, verified via GitHub Actions UI |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-01 | Spoofing | JWT Token Validation | high | mitigate | Backend validates JWT signature on every admin request; invalid/expired tokens return 401; no token fallback to unauthorized access |
| T-05-02 | Tampering | CORS Policy Enforcement | high | mitigate | Backend CORS middleware (AllowSpecificOrigin per D-03) only allows requests from https://housedemoll.com in production; localhost:3000 allowed in dev only; wildcard policy forbidden |
| T-05-03 | Tampering | API Response Tampering | medium | accept | HTTPS enforced by GitHub Pages + Heroku; traffic encrypted in transit; accept risk that MitM could modify unencrypted cookies (mitigated by avoiding cookie-based auth) |
| T-05-04 | Repudiation | Audit Trail | low | defer | Admin actions (create/edit/delete) logged to database with timestamp; deferred to Phase 2 (post-MVP) for full audit trail UI |
| T-05-05 | Disclosure | Database Credentials | high | mitigate | DATABASE_URL environment variable injected at runtime by Heroku; never committed to source; JWT_SECRET same treatment; no secrets in .env files committed to git |
| T-05-06 | Disclosure | Frontend .env.production | medium | accept | VITE_API_BASE is public (frontend will make public API requests anyway); no secrets in .env.production; backend URL is discoverable from network tab |
| T-05-07 | Denial of Service | Rate Limiting | low | defer | No rate limiting in Phase 5; Heroku free tier limits connections; acceptable for MVP; implement rate limiting in Phase 2 if abuse occurs |
| T-05-08 | Elevation of Privilege | Token Bypass | high | mitigate | Admin endpoints require valid JWT in Authorization header; no bypass routes; login endpoint validates credentials against stored hash; session hijacking mitigated by short token expiry (24 hours) |
| T-05-09 | Tampering | E2E Test Credentials | medium | mitigate | Test credentials (admin@example.com / Password123!) used only in E2E tests; never expose in CI/CD logs (GitHub Actions mask secrets via **); separate production credentials from test data |
| T-05-SC | Tampering | npm/pip/cargo installs | high | mitigate | Playwright, GitHub Actions actions, and npm dependencies checked for legitimacy; use pinned versions in package-lock.json; audit npm packages before install (npm audit); blocking checkpoint for any ASSUMED or SUS packages |

</threat_model>
