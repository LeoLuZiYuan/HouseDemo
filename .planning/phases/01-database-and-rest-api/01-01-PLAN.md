  <action>
    Set up a minimal end-to-end slice that proves all layers work together:

    1. **PostgreSQL Setup & Schema**
       - Start PostgreSQL locally (or via Docker Compose as documented alternative)
       - Create database `housedb`
       - Create `properties` table with schema matching rooms.json structure:
         * `id` (UUID or serial int, primary key)
         * `name` (varchar)
         * `area` (varchar)
         * `monthlyRent` (varchar, storing as string like "NT$12,800")
         * `shortDesc` (text)
         * `description` (text)
         * `features` (text array or JSONB, serialized as JSON in API response)
         * `coverImage` (text, URL)
         * `images` (text array or JSONB, serialized as JSON in API response)
         * Timestamps optional for V1 (created_at, updated_at)

    2. **Seed Data**
       - Create `Seed.sql` with INSERT statements for all 4 properties from rooms.json
       - Run seed script to populate 4 rows (verify count = 4)
       - Commit seed.sql for reproducibility

    3. **.NET Minimal API Setup**
       - Create `src/backend/` directory structure
       - `Program.cs`: 
         * Set up minimal API host
         * Configure CORS (allow requests from frontend origin, e.g., localhost:5173 for Vite dev, add GitHub Pages domain for production)
         * Register database and repository services (dependency injection)
         * Wire GET /api/properties and GET /api/properties/{id} endpoints (READ-ONLY for tracer)
       - `appsettings.json`:
         * Database connection string pointing to local PostgreSQL
         * Store securely (not in git); use environment variables in production
       - `appsettings.Development.json` for local overrides (optional, add to .gitignore if sensitive)

    4. **Data Models**
       - `Models/Property.cs`: Plain C# class matching properties table schema
         * Naming: PascalCase properties (Id, Name, Area, MonthlyRent, ShortDesc, Description, Features, CoverImage, Images)
         * Features and Images as `List<string>` or `string[]` (serialized to/from JSONB or text array in DB)

    5. **Data Access (Dapper)**
       - `Data/Database.cs`:
         * IDbConnection factory using Npgsql (NuGet: Npgsql)
         * Dependency injection registration
       - `Data/PropertyRepository.cs`:
         * `GetAllProperties()` → SELECT * FROM properties → List<Property>
         * `GetPropertyById(id)` → SELECT * FROM properties WHERE id = @id → Property or null
         * Use Dapper `.Query<Property>()` and `.QueryFirstOrDefault<Property>()`
         * Handle JSONB/array deserialization (Dapper can map to C# List if configured, or parse manually)

    6. **API Endpoints**
       - `GET /api/properties` → returns HTTP 200 with JSON array of all properties (or empty array if no data)
       - `GET /api/properties/{id}` → returns HTTP 200 with single property or HTTP 404 if not found
       - Response format (JSON): `{ "id": "...", "name": "...", "area": "...", "monthlyRent": "...", "shortDesc": "...", "description": "...", "features": [...], "coverImage": "...", "images": [...] }`

    7. **Verification**
       - Start backend: `dotnet run` (or `dotnet watch run` for dev)
       - Test locally: `curl http://localhost:5000/api/properties` → should return array with 4 properties
       - Test single: `curl http://localhost:5000/api/properties/yongan-suite` (or ID) → should return one property
       - Verify JSON structure is valid and complete
       - Commit seed.sql and backend code

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Frontend ↔ Backend API | Untrusted HTTP requests from browser (CORS, input validation needed) |
| Backend ↔ Database | Trusted internal connection (local network for V1); credentials in environment variables |
| External URLs | Property images sourced from external Cloudinary URLs (user controlled in admin panel, Phase 3) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Spoofing | API endpoints | low | accept | Public read-only endpoints in Phase 1 (no authentication yet); auth added in Phase 2 |
| T-01-02 | Tampering | GET /api/properties | low | mitigate | Read-only endpoints; write endpoints (POST/PUT/DELETE) added in Phase 3 with auth + validation |
| T-01-03 | Repudiation | Database queries | low | accept | Audit timestamps (CreatedAt, UpdatedAt) optional for Phase 1; logging in Phase 2+ |
| T-01-04 | Information Disclosure | Connection string | medium | mitigate | Store DB credentials in environment variables, never in source code; .env in .gitignore |
| T-01-05 | Denial of Service | GET /api/properties | low | accept | No rate limiting in Phase 1; public read-only endpoint; add if needed in Phase 5 |
| T-01-06 | Elevation of Privilege | API access | low | accept | Phase 1 has no authentication; all endpoints public; admin routes protected in Phase 2 |
| T-01-SC | Tampering | npm/pip/cargo installs | high | mitigate | NuGet (C#) packages: verify Npgsql, Dapper legitimacy on nuget.org before install; no suspicious dependencies |
