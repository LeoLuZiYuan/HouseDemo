<objective>
**Phase 2: Admin Authentication — Secure Landlord Access**

Implement a complete authentication system protecting the admin panel from unauthorized access. This phase proves the auth architecture end-to-end: login endpoint accepting credentials, JWT token generation, backend middleware validating tokens, and frontend login form storing and using the token for protected API calls.

**Purpose:** Establish the security boundary for the admin panel (Phase 3 CRUD operations) and ensure only the landlord can manage properties.

**Output:** Working login endpoint, JWT token validation, protected admin routes, LoginView.vue component, and client-side token storage. End-to-end: landlord enters credentials → receives token → calls protected API → success.

**Tracer Slice:** Single end-to-end path — login form submission → backend validation → JWT token generation → store in localStorage → call protected endpoint with token → success response.
</objective>

    1. **AuthModels.cs** — Define request/response contracts:
       - `LoginRequest`: { email (string), password (string) }
       - `AuthResponse`: { token (JWT string), expiresIn (int, hours), tokenType ("Bearer") }
       - `TokenClaims`: Payload to encode in JWT (user id/email, roles, issued timestamp)

    2. **AuthService.cs** — Core authentication logic:
       - `VerifyCredentials(email, password)` → query env vars LANDLORD_EMAIL, LANDLORD_PASSWORD_HASH; use BCrypt.Net-Next (NuGet) to verify password against stored hash; return bool
       - `GenerateToken(email)` → create JWT using System.IdentityModel.Tokens.Jwt (NuGet: System.IdentityModel.Tokens.Jwt); include email, IssuedAt, ExpiresAt (24 hours); sign with JWT_SECRET from env var; return token string
       - `ValidateToken(token)` → parse JWT, verify signature using JWT_SECRET, check expiry, return TokenClaims or null if invalid
       - Constructor: inject IConfiguration to read env vars (LANDLORD_EMAIL, LANDLORD_PASSWORD_HASH, JWT_SECRET, JWT_EXPIRY_HOURS)

    3. **Program.cs** — Wire auth routes and CORS:
       - Register AuthService in DI container
       - Add POST /api/auth/login endpoint:
         * Accept LoginRequest from JSON body
         * Call AuthService.VerifyCredentials(email, password)
         * If valid: call GenerateToken() → return 200 + AuthResponse JSON
         * If invalid: return 401 Unauthorized + error message (e.g., "Invalid credentials")
       - Add GET /api/admin/properties endpoint (protected tracer slice):
         * Extract Authorization header (format: "Bearer {token}")
         * Call AuthService.ValidateToken(token)
         * If valid: return list of properties (same as Phase 1 GET /api/properties, but admin route)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser ↔ Backend API | Untrusted HTTP requests; token in Authorization header must be validated |
| Frontend ↔ localStorage | Semi-trusted storage; token accessible to XSS attacks (mitigated by secure development practices) |
| Backend ↔ JWT Token | Trusted: JWT signed with server secret; signature verified on every request |
| Admin Panel ↔ Protected Routes | Trusted: only authenticated requests reach admin endpoints |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Spoofing | POST /api/auth/login | medium | mitigate | Validate email/password against env vars (LANDLORD_EMAIL, LANDLORD_PASSWORD_HASH); rate-limit login attempts (Phase 2.1) |
| T-02-02 | Tampering | JWT Token | medium | mitigate | Token signed with JWT_SECRET; signature verified on every protected route; token expiry enforced (24 hours) |
| T-02-03 | Repudiation | Login audit log | low | accept | Log authentication attempts (success/failure) with timestamp; Phase 2.1 or Phase 5 add audit trail |
| T-02-04 | Information Disclosure | Password in transit | medium | mitigate | HTTPS enforced in production (Heroku auto-enables); Phase 1+ use HTTPS only |
| T-02-05 | Information Disclosure | Password storage | high | mitigate | Use BCrypt hashing (not plaintext); password_hash never logged or displayed; stored as env var only |
| T-02-06 | Denial of Service | POST /api/auth/login | low | accept | No rate limiting in Phase 2 MVP; add in Phase 2.1 if brute-force testing shows risk |
| T-02-07 | Elevation of Privilege | Protected routes | high | mitigate | Middleware validates token on every /api/admin/* request; unauthenticated requests return 401 |
| T-02-08 | Information Disclosure | localStorage token | medium | mitigate | Token stored in localStorage (accessible to XSS); Phase 2.1 consider HttpOnly cookies; use CSP headers (Phase 5) |
| T-02-09 | Tampering | JWT secret | critical | mitigate | JWT_SECRET stored in environment variables (never in code); Heroku config vars for production; rotate on suspected breach |
| T-02-SC | Tampering | npm/pip/cargo installs | high | mitigate | NuGet packages: verify BCrypt.Net-Next, System.IdentityModel.Tokens.Jwt, System.IdentityModel.Tokens.Jwt.Handlers on nuget.org; no typosquatting |

</threat_model>
