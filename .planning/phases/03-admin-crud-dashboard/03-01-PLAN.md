<objective>
**Phase 3: Admin CRUD Dashboard — Landlord Property Management**

Implement complete create, read, update, and delete (CRUD) operations for property listings. This phase delivers a working admin dashboard where the landlord can manage their entire property portfolio through a form-based interface backed by database persistence and REST endpoints.

**Purpose:** Enable landlord to independently manage property listings without modifying source code or static files. All changes immediately reflect on the public site.

**Output:** 
- Backend CRUD endpoints: POST, PUT, DELETE /api/admin/properties with validation
- Frontend dashboard: table view of all properties with action buttons
- Frontend forms: create and edit property details with client-side validation
- End-to-end: landlord fills form → submitted to backend → validated → persisted → dashboard and public site immediately updated

**Tracer Slice:** One complete create property path — PropertyFormView (new property) → form validation → POST /api/admin/properties → backend validation → Dapper INSERT to database → response to frontend → AdminDashboardView re-fetches and displays new property. Build ONE end-to-end create property path: PropertyFormView form submission → client-side validation → POST /api/admin/properties → backend validation → Dapper INSERT → return new property to frontend → verify in database.

**Backend (Dapper + .NET):**
1. Create `PropertyModels.cs` with `CreatePropertyRequest` (name, area, monthlyRent, shortDesc, description, features string, images string, coverImage), `PropertyResponse` with all fields plus id and timestamps
2. Create `PropertyService.cs` with method `ValidateProperty(request)` checking: name not empty, area > 0, monthlyRent > 0, shortDesc not empty, description not empty, images/features are valid (comma-separated strings or empty); return validation errors list
3. Create `PropertyService.InsertProperty(request)` using Dapper: construct INSERT query inserting all fields (features and images stored as JSON strings), return new property with generated id
4. In `Program.cs` add POST `/api/admin/properties` endpoint: require JWT token (AuthMiddleware already protecting /api/admin/*), deserialize CreatePropertyRequest, call ValidateProperty, return 400 with errors if invalid, call InsertProperty, return 201 with PropertyResponse
5. **Error handling:** catch Dapper exceptions (e.g., database constraint violations), log, return 500 with generic error message (not internal details)

**Frontend (Vue 3):**
1. Create `usePropertyApi.js` composable with method `createProperty(propertyData)`: POST to `/api/admin/properties` with Authorization header from useAuth, return response or throw error with message
2. Create `PropertyFormView.vue` component for NEW property:
   - Form fields: name (text input), area (number), monthlyRent (number), shortDesc (textarea), description (textarea), features (textarea with instruction "comma-separated: WiFi, Parking, etc."), images (textarea with instruction "comma-separated URLs"), coverImage (text input for single URL)
   - Client-side validation: on submit, check all required fields not empty, area and rent are positive numbers, at least one image URL provided; if validation fails, show error messages in red, do NOT submit
   - On form submit (after validation passes): call `usePropertyApi.createProperty()`, show loading spinner, on success navigate to AdminDashboardView, on error show error message
   - **No hardcoded data**, all from form inputs; **features and images collected as strings, sent as-is to backend** (backend will store as JSON)

**Verification:**
- POST to `/api/admin/properties` with valid data → 201 response with new property object including id
- POST to `/api/admin/properties` with invalid data (missing name, negative rent, etc.) → 400 response with validation error messages
- Database INSERT verified: query PostgreSQL directly, new row exists with correct field values
- Frontend form submission → POST succeeds → no errors displayed
- **No manual refresh needed** — verify the end-to-end flow completes without manual UI refresh

**Acceptance:** Landlord fills PropertyFormView, submits, gets 201, property appears in database with all fields correct, no errors on form.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → Backend API | Untrusted HTTP requests cross here; must validate all input |
| Frontend → LocalStorage | Token stored; vulnerable to XSS but acceptable for MVP learning project |
| Database | Trusted data source; Dapper parameterized queries prevent SQL injection |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Spoofing | POST /api/admin/properties without token | high | mitigate | AuthMiddleware requires Authorization header with valid JWT token; reject 401 if missing/invalid |
| T-03-02 | Tampering | Modify form fields client-side to inject malicious data | high | mitigate | Server-side validation in PropertyService.ValidateProperty() rejects unexpected types/formats; Dapper parameterized queries prevent SQL injection |
| T-03-03 | Repudiation | Admin denies deleting a property | low | accept | DELETE is destructive but confirms user intent via dialog; audit timestamps (created_at, updated_at) in database provide traceability; suitable for single-owner MVP |
| T-03-04 | Information Disclosure | GET /api/admin/properties exposes all properties to unauthorized user | high | mitigate | Require JWT token on GET /api/admin/properties; compare to public GET /api/properties (no auth required, read-only) |
| T-03-05 | Denial of Service | Large form submission or bulk deletes | low | accept | Input size limits handled by HTTP server defaults; single-owner MVP does not require rate limiting |
| T-03-06 | Elevation of Privilege | Non-landlord claims to be landlord | high | mitigate | JWT token generated only by POST /api/auth/login after validating email/password against environment variables; token contains no user ID (single-owner) |

</threat_model>
