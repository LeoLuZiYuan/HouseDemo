## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Visitor → Frontend | User-provided URL params (property ID) — must validate before fetch |
| Frontend → Backend | Untrusted API responses — validate property shape, null checks |
| Database → API | Trusted internal; backend already validates at insert time |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Tampering | Route params ({id}) | Medium | Mitigate | Frontend validates route.params.id is alphanumeric before API call; backend returns 404 for invalid ID |
| T-04-02 | Info Disclosure | Frontend → /api/properties | Low | Accept | Public endpoint (no auth required); property data already public; no secrets in response |
| T-04-03 | DoS | Client-side fetch loops | Low | Mitigate | Limit retry attempts in error handler (e.g., max 3 retries); add exponential backoff if needed in V2 |
| T-04-04 | Tampering | API response validation | Medium | Mitigate | Frontend checks for required fields (id, name, area, monthlyRent) before rendering; null checks prevent crashes |
| T-04-SC | Tampering | npm/pip/cargo installs | High | Mitigate | No new packages added in Phase 4; reuse Phase 3 stack (Vue 3, Vite) |

</threat_model>
